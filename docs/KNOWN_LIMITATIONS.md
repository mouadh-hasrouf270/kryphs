# Known limitations and acceptance gaps

This is a working local platform, not a claim of complete production acceptance against the master specification. The following items remain:

1. **Real provider acceptance:** no Google/YouTube/Meta credentials were supplied. Transport/safety behavior is tested with explicit fixtures, but live account authorization, quotas, uploads, Meta creative requirements and real insights still need testing.
2. **Provider coverage:** TikTok and Google Ads live performance synchronization and publishing are not implemented. Their connection records/manual performance workflows exist; unsupported operations fail clearly. Meta publishing supports locally available video masters and creates paused ads.
3. **Drive organization/scope:** folder mappings currently create per-creative roots, not the complete workspace/brand/product/campaign/request/version hierarchy. Initial inventory includes files accessible through the connection, rather than a root-subtree-only traversal. Use dedicated/narrow connections. OAuth disconnect deletes local credentials; revoke the account grant in Google separately. The YouTube OAuth scope toggle is currently API-only.
4. **Media processing:** binary signatures and image dimensions are validated, but antivirus scanning, video probing/transcoding, thumbnail generation, automated transcription/OCR and media previews are not bundled. Content text and human corrections can be managed manually.
5. **Advanced evidence/search:** search uses a portable scoped `icontains` fallback, not ranked FTS5. Evidence includes latest metrics, sample counts, type/outcome groups and fatigue signals; the full legacy hook/CTA/clip/family analytics and advanced evidence assistant are not all reproduced. Lineage is a relationship view, not a complete interactive graph.
6. **Experiment analysis:** lifecycle/arm binding/learning are implemented. Full statistical comparison, confidence calculations and automatic winner selection are not supplied. The application does not infer causality.
7. **Automation:** rules support exact-match creative type/status/outcome conditions and notify/refresh-proposal actions. Full nested rule-builder logic, arbitrary time-based rules and automatic publishing are not supported. Schedule `scan_deadlines` externally for deadline reminders.
8. **Legacy migration:** fifteen principal entity types are supported; other populated tables are explicitly reported and block default import. Memberships, provider secrets and all historic deployment/knowledge/automation data are not fully migrated. No real legacy database was supplied. Large imports use one atomic batch rather than bounded resumable batches.
9. **Localization/UX:** Arabic RTL and primary navigation/workflow labels are implemented and browser-tested. Some advanced field labels fall back to English, especially French; server validation messages are English. Several supporting domains use shared forms/tables instead of dedicated rich editors. Advanced membership restrictions/permission overrides require the API; not every API operation has a dedicated visual control.
10. **Scale/operations:** one SQLite worker is the supported default. Login throttling uses a process-local cache; use edge/shared-cache limiting before multiple web processes. Long sync operations do not heartbeat between every provider page. The operations interface shows job records but does not implement every stale-sync aggregate in the specification.
11. **Backups:** the database uses a safe online snapshot. Local media copying occurs afterward; pause uploads/jobs for a fully consistent DB-plus-media backup. Encryption key rotation tooling is not included.
12. **Docker verification:** the Docker build reached image export but Docker Desktop returned containerd layer-extraction `input/output error` while C: free space dropped sharply. Compose now reuses a single backend image. A complete container deployment/HTTPS smoke test has not passed in this environment. Native checks/builds are separate and are recorded in FINAL_QA_REPORT.md.
13. **Acceptance coverage:** tests cover important lifecycle, isolation and receipt invariants, not every requirement or failure permutation. Full accessibility, localization, concurrency/load and real-provider security review remain before company-wide production use.

These gaps are not represented as completed milestones. No feature is made to appear successful through fake provider IDs or production mock fallbacks.
